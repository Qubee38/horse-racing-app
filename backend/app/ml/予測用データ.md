# 競馬予測システム - 特徴量処理の完全ガイド

## 概要

予測実行時のデータフローと特徴量処理の全体像を説明します。スクレイピングから最終的なモデル入力まで、各段階で何が行われるかを詳細に記録します。

---

## データフロー全体図

```
1. Netkeibaスクレイピング
   ↓ (127列のCSV生成)
2. 特徴量エンジニアリング
   ↓ (派生特徴量追加 → 130列)
   ↓ (騎手勝率結合 → 133列)
   ↓ (不要列削除 → 95列)
3. モデル入力準備
   ↓ (データ型変換、NaN保持)
4. LightGBM予測
```

## 2. 特徴量エンジニアリング段階（feature_engineering.py）

### 入力

### 処理フロー

#### Step 1: データ読み込み

#### Step 2: 派生特徴量の計算
```python
def _calculate_derived_features(df):
    # 1. 斤量を数値変換
    kinryo_columns = ['斤量', '斤量1', '斤量2', '斤量3', '斤量4', '斤量5']
    for col in kinryo_columns:
        df[col] = pd.to_numeric(df[col], errors='coerce')
    
    # 2. 平均斤量計算（過去5走 + 現在）
    df['平均斤量'] = df[kinryo_columns].mean(axis=1, skipna=True)
    
    # 3. 距離差計算（現在 - 前走）
    df["距離差"] = pd.to_numeric(df["距離"], errors='coerce') - pd.to_numeric(df["距離1"], errors='coerce')
    df["距離差1"] = pd.to_numeric(df["距離1"], errors='coerce') - pd.to_numeric(df["距離2"], errors='coerce')
    # ... 距離差2〜4も同様
    
    # 4. 日付を文字列化（datetime変換前）
    date_columns = ["日付", "日付1", "日付2", "日付3", "日付4", "日付5"]
    for col in date_columns:
        df[col] = df[col].astype(str)
    
    # 5. 日付差計算（日数差）
    df["日付差"] = (pd.to_datetime(df["日付"], errors='coerce') - pd.to_datetime(df["日付1"], errors='coerce')).dt.days
    # ... 日付差1〜4も同様
    
    return df
```

**カラム数:** 127列（変化なし、値のみ更新）

#### Step 3: 騎手勝率の結合
```python
def _merge_jockey_win_rates(df):
    # 1. 騎手名の表記ゆれを統一
    df = df.replace({
        "ムルザバエフ": "ムルザバ",
        "デムーロ": "Ｍ．デム",
        # ... その他の表記ゆれ
    })
    
    # 2. 騎手勝率データと結合
    jockey_df = pd.read_csv('data/reference/jockey_win_rate.csv')
    df = df.merge(jockey_df[['騎手', '勝率', '連対率', '複勝率']], 
                  on='騎手', how='left')
    
    # 3. 結合されなかった騎手のデフォルト値設定
    df['勝率'] = df['勝率'].fillna('')
    df['連対率'] = df['連対率'].fillna('')
    df['複勝率'] = df['複勝率'].fillna('')
    
    return df
```

**カラム数:** 130列（勝率、連対率、複勝率の3列追加）

#### Step 4: モデル入力用前処理（95特徴量）

```python
def prepare_model_input(features_df):

    drop_columns = [

        '馬', '騎手', 'レース名', '場名', '開催', '日付', 'race_id', 
        '体重', '体重変化',
        
        # 予測時に存在しないデータ（削除対象）
        '走破時間', 'オッズ', '通過順', '着順', '上がり', '人気',
        
        # 過去戦績の日付・騎手（削除対象）
        '日付1', '日付2', '日付3', '日付4', '日付5',
        '騎手1', '騎手2', '騎手3', '騎手4', '騎手5',
        
        # 過去戦績の場id・回り（削除対象）
        '場id1', '場id2', '場id3', '場id4', '場id5',
        '回り1', '回り2', '回り3', '回り4', '回り5'
    ]
    
    model_input_df = features_df.drop(columns=drop_columns, errors='ignore')
    
    return model_input_df
```

## 3. モデル入力準備段階（predictor.py）

### 処理内容

```python
def _prepare_dataframe_for_model(model_input_df):
    prepared_df = pd.DataFrame()
    
    for col in feature_columns:  # モデルが期待する95特徴量
        if col in model_input_df.columns:
            values = model_input_df[col].copy()
        else:
            values = pd.Series([np.nan] * len(model_input_df))
        
        # 空文字のみをNaNに変換
        values = values.replace('', np.nan)
        
        # 数値変換（変換できないものはNaN）
        values = pd.to_numeric(values, errors='coerce')
        
        # ⚠️ 重要: fillna(0.0)を実行しない
        # NaNはそのまま保持してLightGBMに渡す
        
        prepared_df[col] = values
    
    return prepared_df
```

### 出力
**DataFrame（95列、全て数値型）**

**データ型:**
- `float64`: 全カラム
- 値:
  - 通常の数値: そのまま
  - **NaN: 欠損データとして保持**（0.0に変換しない）

## 重要な注意事項

### 1. NaNと0.0の扱い

**絶対に守るべきルール:**
```python
# ❌ 間違い
values = values.fillna(0.0)  # NaNを0に変換してはいけない

# ✅ 正しい
values = pd.to_numeric(values, errors='coerce')  # NaNはそのまま
```

**理由:**
- LightGBMはNaNと0.0を**全く別の値**として扱う
- 過去戦績でデータ取得できなかった項目（天気、馬場など）はNaNとして保持
- NaNを0に変換すると予測結果が大きく変わる

### 2. デフォルト値の扱い

**スクレイピング時:**
```python
# ❌ 間違い
weather = tenki_mapping.get(weather_text, 0)  # デフォルト値0

# ✅ 正しい
weather = tenki_mapping.get(weather_text)  # デフォルト値None
```

### 3. 削除対象列

予測時に存在しないまたは不要な列:
- `走破時間`, `オッズ`, `通過順`, `着順`, `上がり`, `人気` - 予測時は未確定
- `馬`, `騎手`, `レース名`, `場名`, `開催` - 識別情報
- `日付`, `日付1〜5` - 日付差に変換済み
- `騎手1〜5`, `場id1〜5`, `回り1〜5` - 不要な過去データ

### 4. 特徴量の順序

モデルが期待する順序:
```
1. 馬番
2. 性
3. 齢
4. 斤量
...
95. 複勝率
```

`_prepare_dataframe_for_model()`でモデルが期待する順序に並び替え。
